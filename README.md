# Text-to-SQL Generation with a Fine-Tuned Transformer

Project 5 (Generative AI Applications): fine-tunes **CodeT5-small** (`Salesforce/codet5-small`) to generate SQL queries from an English question and a `CREATE TABLE` schema.

| File | Contents |
|---|---|
| `generative_model.ipynb` | Data inspection, model, training, generation, evaluation, summary (executed, with outputs) |
| `module_summary.pdf` | Generative AI analysis and ethics report with APA references |
| `requirements.txt` | `pip freeze` of the environment used |
| `data/sql_create_context.csv` | Dataset copy (78,577 rows: `question`, `context`, `answer`) |
| `outputs/` | Training log/history, figures, test predictions and metrics |

## Data source
[`b-mc2/sql-create-context`](https://huggingface.co/datasets/b-mc2/sql-create-context) (CC BY 4.0), loaded with `datasets.load_dataset("b-mc2/sql-create-context")`.
Questions and SQL are human-written and come from WikiSQL (Zhong et al., 2017) and Spider (Yu et al., 2018). The schema column was derived from each gold query by a script, not generated by AI.
If the CSV is missing, the notebook downloads the dataset and recreates it.

## Results (3,941 test questions on schemas unseen in training)
Exact match 82.0% · execution accuracy 88.5% · valid SQL 96.2%. Multi-table `JOIN` queries remain hard (16.0% exact match).

## Reproduce
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/jupyter nbconvert --to notebook --execute generative_model.ipynb --inplace
```
Training takes about 72 minutes on an Apple M1 Pro (MPS) and is faster on a CUDA GPU. The fine-tuned checkpoint is written to `models/`, which is git-ignored.

Note: `transformers` is pinned below 5.0, because the CodeT5 tokenizer config fails to load under transformers 5.x.
